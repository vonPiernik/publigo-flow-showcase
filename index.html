Na czym polegają zwrotki JSON?

Tworzenie przepływów opiera się na kontrakcie z agentem: każdy węzeł agent kończy pracę odpowiedzią w ustalonym formacie — najczęściej result.json. Flow nie zgaduje, co agent „miał na myśli” — czyta konkretne pola i na nich podejmuje decyzje o kolejnych krokach.

1. Kontrakt result.json

Agent zwraca strukturalną odpowiedź, np. security review:

{
  "verdict": "success",
  "findings": [],
  "confidence": "high",
  "summary": "Brak istotnych ustaleń — diff nie dotyka autoryzacji."
}

Pola verdict, findings, confidence to kontrakt — od nich zależy dalszy bieg flowa.

2. Krawędzie warunkowe when

Kolejny krok wybierany jest na podstawie zwrotki poprzedniego węzła:

output.verdict == 'success'  → idź dalej
output.verdict == 'needs_fix' → pętla z pytaniem do usera

Przy wielu krawędziach wygrywa pierwszy pasujący warunek.

3. Bramki, decyzje i pętle

Węzeł user_input pokazuje człowiekowi output agenta; człowiek wybiera accept albo comments — a comments wraca do agenta jako feedback (pętla z limitem, np. max 12 rund).

Bramka może też auto-skipować, gdy kontrakt jest „czysty”:

skip_when:
  output.verdict == 'success'
  output.confidence == 'high'
  empty(output.findings)
